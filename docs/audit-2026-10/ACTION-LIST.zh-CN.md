## 10. 第十一轮补充（O1–O4）

第十一轮扫的是**更新链执行层**——这是二开版里风险最高的一条链，因为它会下载并执行外部代码。结论和前面十轮相反：**这一轮没有 P2，也没有值得插队的项**。整条链的加固水平（zip-slip 全维度拒绝、逐文件哈希、journal 回滚、父进程三重身份校验、asInvoker）明显高于仓库其余部分。

| 编号 | 标题 | 归入 | 理由 |
|---|---|---|---|
| **O2** [P3] | 取消更新后 300 MB 已下载包不清理 | 第二批 | 在 `if (!exited)` 分支加 4 行 `try { Directory.Delete(session, true); } catch (IOException) { } catch (UnauthorizedAccessException) { }`；纯收益，无风险 |
| **O1** [P3] | 更新页直出英文 .NET 异常原文 | 第二批（与 C5 同做） | C5 已经在做"异常映射到本地化文案"，更新页是同一个映射函数的另一个调用点，顺手一起做最省事 |
| **O3** [P3] | `Dispose()` 后仍 `Changed?.Invoke()` | 第四批 | 3 行（`_disposed` 标志 + 提前返回），但当前无可观察故障，不急着改 |
| **O4** [P3] | `UpdateWindowInput` 构造中途抛异常 → 窗口永久禁用 | 第三批（需拍板） | 修法简单（两段式），但"某个窗口此刻没有 HWND"这个前提我无法静态确证；需要作者确认外部便签/待办窗口的创建时序，再决定是改代码还是加断言 |

> **一句话结论**：如果只允许改三处更新链代码，改 O2、O1、O3 就够；O4 先确证再动。真正需要作者拍板的仍然是 C1（签名）、C2+J1（身份分家）、F6（异常白名单）这三件，它们都在更新链之外。
